# 화면 (5단계)

단일 페이지 셸([app/page.tsx](../app/page.tsx))에서 화면 전환. 비활성 화면은
`display:none`으로 유지해 리플레이 세션 등 상태를 보존한다. 디자인은
Claude Design 시안(`K-PaperTrade.dc.html`) 기반, 상승=빨강/하락=파랑(한국식).

| 화면 | 컴포넌트 | 데이터 |
|---|---|---|
| 대시보드 | Dashboard | portfolio·orders·performance API. 수익률 곡선은 일일 스냅샷 2개↑부터, 벤치마크는 indices |
| 종목 상세 | StockDetail | 최근 거래일 분봉(lightweight-charts 캔들+거래량), 수급, 주문 패널(라이브 계좌) |
| 리플레이 | Replay | 서버 세션 기반 — 아래 참조 |
| 주문·체결 | Orders | 계좌 주문 + 체결·거부 사유 뱃지 |
| AI 판단 로그 | AiLog | ai-decisions (ret_d5/20/60은 6단계 배치가 채움) |

공용: OrderPanel(주문 패널 — 예상 비용은 엔진 `estimateCost` 직접 사용),
client.ts(fetch 헬퍼), lib/market-hours.ts(장시간 판별).

## 장중 폴링

- 종목 상세 화면에서 **보고 있는 종목만**, 60초 간격, 평일 09:00~15:30 KST +
  탭이 보일 때만(`document.visibilityState`). 공휴일은 판별하지 않음 —
  휴일엔 빈 응답을 받을 뿐.
- 흐름: `/quotes` 프록시 → 서버가 분봉 캐시 upsert + 라이브 PENDING 정산 →
  클라이언트가 당일 분봉 재조회로 차트 갱신.

## 리플레이 재생

- 날짜·종목 선택 → 서버 세션 자동 생성(같은 조합 중복 생성 가드).
  날짜 목록은 005930 분봉 존재 여부로 최근 12일을 탐색해 구성.
- 재생: 클라이언트 타이머가 tick API를 배치 호출 —
  1x=900ms/1분, 10x=450ms/5분, 60x=500ms/30분 (요청 중복 방지 inflight 가드).
- 차트는 매 tick 후 `minutes?session=` 재조회 — 서버가 커서로 잘라 주므로
  클라이언트에 미래 분봉이 아예 없다.
- 스크러버는 전진 전용(되감기 = 새 세션). 15:30 도달 시 자동 종료 +
  결과(result_json) 저장 → 세션 목록에서 비교 가능.
- 체결/거부는 tick 응답 fills로 수신 — 상·하한가 거부는 모달, 나머지는 토스트.

## 알려진 한계 (v1)

- 수익률 곡선·수급·일봉은 장 마감 배치가 쌓여야 표시된다 (빈 상태 UI 제공)
- 리플레이 되감기 없음, 여러 종목 동시 리플레이는 세션 생성 API만 지원(UI는 단일)
- 라이브 주문 체결은 장중 폴링이 돌 때만 판정된다 (서버리스 상시 잡 없음)
