# AI 판단 엔진 (claude -p)

`collector/decide.py` — 시총 상위 N종목과 보유 종목에 대해 opus·sonnet이 BUY/SELL/HOLD를 정하고,
판단을 `ai_decisions`에 기록한 뒤 상한을 통과한 것만 주문으로 낸다. 주문은 키움 **모의투자**
계좌에 미러링되고 체결은 키움이 한다(`collector/kiwoom_order.py`).

2026-10에 고친 것과 그 근거는 [diagnosis-2026-10.md](diagnosis-2026-10.md), 코어·위성 구조는
[core-satellite.md](core-satellite.md).

## 언제 도는가

평일 **10:30 / 12:30 / 14:30 KST**. cron-job.org가 `POST /api/v1/cron/trigger?workflow=decide`
(헤더 `x-cron-secret`)를 부르면 Vercel 라우트가 GitHub `workflow_dispatch`를 쏜다.
GitHub `schedule`은 쓰지 않는다 — 몇 시간씩 밀려 15시대에 예고 없는 4번째 사이클이 되거나
마감 뒤에 떨어졌다. cron-job.org가 멎으면 판단이 조용히 안 도므로 그쪽 실패 알림을 켜 둔다.

판단하지 않는 경우(기록도 남기지 않는다 — 다른 날과 같은 자로 잴 수 없다):

| 조건 | 판정 |
|---|---|
| 장중(평일 09:00~15:29)이 아님 | `market_open` |
| 휴장일 | 당일 분봉이 한 종목도 없으면 건너뛴다(지수 날짜로 묻지 않는다 — 소스가 하루 늦으면 거래일을 건너뛴다) |

## 흐름

1. **판단 대상** — `universe.watchlist(N)`: 시총 상위 N(KONEX·ETF 제외) + 보유 종목(코어 ETF 제외).
   상장목록의 시총이 비어 있으면(캐시의 새벽판) 캐시 저장소의 최근 정상 파일로, 그것도 안 되면
   가장 최근 판단 사이클의 종목으로 폴백한다.
2. **지표**
   - 일봉(`daily_prices`, 최근 60개 — 정규장 종가): 1/5/20일 등락률, MA5·MA20 이격, 거래량/20일평균
   - 분봉(키움에서 당일분 직접 조회): 현재가, 시가 대비, 고저위치, VWAP 이격, 최근 30분
   - 컨센서스(네이버), 공시(DART), 뉴스 헤드라인(구글 뉴스 RSS — 본문은 대개 막혀 제목만)
3. **앙상블** (`ensemble.py`) — opus·sonnet이 같은 프롬프트로 판단한다.
   - BUY: 둘 다 응답하고 둘 다 BUY
   - SELL: 한 모델이라도 SELL이고 BUY가 없으면 실행 (AI가 유일한 손절 경로라 일부러 비대칭)
   - 그 외 HOLD. 투표 내역은 `reason_summary` 앞에 `[opus=.. sonnet=.. →결정 n/N응답]`으로 남는다.
4. **기록** — `POST /ai-decisions`. 판단 시점의 분봉 최신가를 `decision_price`로 적는다(채점 기준가).
5. **주문** — 코어 리밸런스(`plan_core`) → 위성(`plan_orders`) → `POST /orders` → 미러링 스텝이 키움에 전송.

## 프롬프트가 말하는 것

- 투자 원칙: 근거가 여럿 겹칠 때만 확신, 과열 회피, 사실(공시) > 추정(컨센서스) > 분위기(뉴스).
- **진입 위치 규율**(9/7~): 장중 고가권(고저위치 70% 이상)·VWAP 위 추격 매수 억제. 매수에만 적용.
- **매도 규율** — 실행과 같은 말을 한다(2026-10~):
  - SELL은 **보유 전량 청산**이다. 부분 매도는 없다. 전량을 팔 근거가 아니면 HOLD.
  - 목표가 근접 시 차익 실현 / 평가손익 −7% 이하에 반등 신호 없으면 손절 / 악재·20일선 이탈 시 청산 검토.
- **현재 보유**: 수량, 평단, 평가손익(분봉 최신가/평단, 비용 전).
- **거래 비용**(사실만): 매수 0.35%, 매도 0.55%, 왕복 약 0.9%.

빠진 것: "일부 축소·비중 축소" 문구(실행은 언제나 전량이었다), "쏠림이면 일부 매도"(모델은
비중을 모르고 상한은 코드가 강제한다), "네 과거 판단의 성과" 문장(1~5건짜리 원수익률 잡음이었다).

## 주문 경로 차단 조건 (fail-closed)

판정은 순수 함수 `order_block_reason(date, now, account)`에 모여 있고, 주문 직전에 한 번 더 본다.

| 조건 | 왜 |
|---|---|
| 장중이 아님 | 마감 후 주문은 체결될 수 없다 |
| `--date`가 오늘이 아님 | 주문 시각은 언제나 오늘이라 멱등 키와 일일 상한이 비어 버린다. `--date`는 지표 기준일 전용 |
| `AI_ACCOUNT_ID` 미설정 | 계좌를 자동 선택하면 사람 계좌에 AI 주문이 들어간다 |
| `GET` 실패(포트폴리오·당일 주문) | 기본값으로 진행하면 멱등 키·상한이 빈 채 주문이 나간다 → 중단(`ApiError`) |
| 판단 기록 실패 | 그 종목만 주문 후보에서 뺀다 |
| 분봉 최신가 없음 | 그 종목은 "가격 없음"으로 건너뛴다 |

## 안전장치

LLM은 신뢰 경계 밖이다. **수량은 LLM이 아니라 코드가 정한다.**

| 항목 | env | 코드 기본값 | 운영 값(저장소 변수) |
|---|---|---|---|
| 자동 주문 킬 스위치 | `AI_AUTOTRADE` | `0` (판단 기록만) | `1` |
| 1회 주문금액 상한 | `AI_MAX_ORDER_KRW` | 1,000,000 | 2,500,000 |
| 1회 주문수량 상한 | `AI_MAX_QTY` | 100 | — |
| 종목당 최대 비중 | `AI_MAX_POSITION_PCT` | 20 | 25 |
| 일일 최대 주문 건수 | `AI_MAX_ORDERS_PER_DAY` | 5 | — |
| 코어 비중 | `AI_CORE_PCT` | 0 (코어 없음) | 70 |
| 대상 종목 수 | `AI_TOP_N` | 10 | — |

- **멱등 키 = (종목, 오늘, 방향).** 같은 날 같은 방향은 한 번만. 방향이 키에 들어 있어 산 날에도 팔 수 있다.
- **매수**: 금액 상한·현금·종목당 비중·위성 상한(100 − 코어%) 중 가장 작은 예산을 `가격 × 1.3`으로 나눈다.
- **매도**: 보유 전량. 금액 상한을 걸지 않는다(걸면 손절이 부분매도로 끝난다).
- **일일 건수**는 방향을 가리지 않고 거부된 주문과 코어 주문도 센다.
- 스키마 검증(`validate`): 대상 밖 종목, 알 수 없는 action, 중복을 버린다.
- 미러링 상한(`kiwoom_order.py`): 1건 1,000주·1,000만원, 모의 호스트 고정.

## 채점

`daily.update_ai_returns`가 장 마감 수집 때 `ret_d5/d20/d60`을 채운다(정의는
[data-pipeline.md](data-pipeline.md)). 분석에는 `ret_basis='decision' AND ret_d5 IS NOT NULL`만 쓰고,
유효 표본은 관측 수가 아니라 **날짜 수**다.

## 실행

```sh
uv run python decide.py --dry-run --top 5              # API 쓰기 없이 계획만
uv run --env-file ../.env python decide.py --top 10
uv run python test_decide.py                           # 파서·상한·멱등·프롬프트 단위 검증
```

## 알려진 한계

- 판단 신호는 지금까지 우연과 구분되지 않는다(매수는 약하게 나쁜 쪽, 매도는 판단 불가).
  날짜 20여 개로는 ±3%p보다 작은 효과를 가릴 수 없다.
- 매도의 대부분이 opus 한 표로 나간다. 규칙을 바꿀지는 2026-10 프롬프트 수정 20거래일 뒤에 본다.
- 포트폴리오 API의 평가액(종목당·위성 상한 판정에 쓰임)은 전일 일봉 종가 기준이다.
- 거부된 주문도 그날의 멱등 키와 일일 건수를 쓴다(키움 전송 실패의 자동 재전송을 막기 위해 그대로 둔다).
