# AI 판단 엔진 (claude -p)

`collector/decide.py` — 시총 상위 N종목에 대해 Claude가 BUY/SELL/HOLD를 정하고,
판단을 `ai_decisions`에 기록한 뒤 상한을 통과한 것만 실제 주문으로 낸다.
워크플로: `.github/workflows/decide.yml` (평일 05:10 UTC = **14:10 KST, 장중**).

## 왜 장중에 도는가 (cron 18:30 → 14:10 KST)

체결 엔진(`settleOwnerOrders`)은 주문의 `ordered_at` **당일** 분봉만 읽고,
`settlePending`은 `ordered_at`보다 뒤인 봉에서만 체결한다. `POST /orders`의
`ordered_at`은 서버 `nowKst()`다. 그래서 마감 후(18:30) 접수한 주문은 그날 15:30에
끝난 분봉 중 볼 수 있는 봉이 하나도 없어 **영구 PENDING**으로 남는다. 다음 날 정산도
안 된다 — 정산이 접수일 분봉만 보기 때문이다.

선택지는 둘이었다.

1. 접수 시각을 다음 개장으로 미룬다 → 서버가 `ordered_at`을 정하므로 API 변경 필요.
2. 배치를 장중으로 옮긴다 → 워크플로 한 줄.

2번을 택했다. 14:10인 이유:
- 체결에 쓸 분봉이 80분 남는다. Actions cron은 부하에 따라 수십 분 밀리는데,
  밀려서 15:30을 넘기면 `market_open()`이 막아 주문 없이 판단만 기록한다(fail-closed).
- 대신 그 시각엔 collect(16:30 KST)가 아직 안 돌아 **당일 일봉이 없다**. 지표는 전
  거래일까지로 계산된다. 수량 산정은 일봉 종가가 아니라 `GET /quotes`의 실시간
  체결가를 쓰므로, 일봉 지연은 판단 근거의 신선도에만 영향을 준다.
- 마감 후 판단 기록만 남기는 두 번째 cron은 두지 않았다. 멱등 컷이 당일 기록 있는
  종목을 건너뛰므로 두 번째 실행은 아무 일도 하지 않는다.

## 흐름

1. `universe.watchlist(N)` — 시총 상위 N종목 (KONEX 제외)
2. **멱등 컷** — `GET /ai-decisions?limit=200`에서 `source='claude-p'` + 당일 기록이
   있는 종목은 판단 자체를 건너뛴다. 재실행해도 중복 기록·중복 주문이 없다
3. 지표 요약
   - 일봉(krx_market `daily_prices`, 최근 60개): 종가, 1/5/20일 등락률,
     MA5·MA20 이격, 거래량/20일평균, **일봉 개수**(표본이 얇을 때 추세 단정을 막으려고 같이 준다)
   - 분봉(로컬 `data/minute/minute-YYYY-MM-DD.parquet`이 있을 때만): 당일 시/고/저,
     후반 30분 거래량 비중. Actions에서는 collect가 별도 러너라 보통 없다 — 없으면 조용히 생략
4. `claude -p --output-format json`을 subprocess로 호출 (stdin으로 프롬프트,
   cwd는 임시 디렉터리 — 저장소 CLAUDE.md·설정을 컨텍스트로 끌어오지 않게)
5. 응답 JSON의 `result` 텍스트에서 배열 파싱 → 스키마 검증 → `POST /ai-decisions`
   (`source='claude-p'`, `ts`는 실행 시각 KST. `--date`로 과거를 볼 땐 `'그날 15:30'`)
6. **기록에 성공한** BUY/SELL만 상한 판정 → `POST /orders` (MARKET) → `POST /cron/settle`

인증은 `x-cron-secret: $CRON_SECRET` 헤더 하나. 읽기(GET)는 드라이런에서도 실제로
하고, 쓰기(POST)는 `--dry-run`에서 전부 로그만 남는다.

## 주문 경로 차단 조건 (fail-closed)

판단 기록은 언제나 하지만, 아래 중 하나라도 걸리면 **주문은 한 건도 나가지 않는다**.
판정은 순수 함수 `order_block_reason(date, now, account)` 한 곳에 모여 있다.

| 조건 | 왜 |
|---|---|
| 장중(평일 09:00~15:29 KST)이 아님 | 마감 후 접수분은 체결될 분봉이 없어 영구 PENDING. 15:30(마지막 봉)도 뒤에 올 봉이 없어 제외 |
| `--date`가 오늘(KST)이 아님 | 주문의 `ordered_at`은 언제나 오늘이라, 과거 날짜를 주면 멱등 키와 일일 상한이 동시에 비어 중복·초과 주문이 된다. `--date`는 **지표 기준일 전용** |
| `AI_ACCOUNT_ID` 미설정 | 계좌를 자동 선택하면 사람이 쓰는 계좌에 AI 주문이 들어간다 |
| `GET`(판단 기록 목록·포트폴리오·당일 주문·시세) 실패 | 조회 실패를 기본값으로 넘기면 멱등 키와 일일 상한이 빈 채로 주문이 나간다. 실패는 곧 중단(`ApiError`, 종료코드 1) |
| `POST /ai-decisions` 실패 | 멱등 키가 이 기록 하나뿐이다. 기록 없이 주문하면 다음 실행이 중복 주문을 낸다 — 기록 실패 종목만 후보에서 뺀다 |
| `GET /quotes`에 시세 없음(휴장·미거래) | 분봉이 없는 날 접수하면 영구 PENDING. 주중 공휴일을 여기서 거른다 |

## 안전장치

LLM은 신뢰 경계 밖이다. **수량은 LLM이 아니라 `plan_orders`가 정한다** — 프롬프트에
수량을 쓰지 말라고 명시했고, 써 보내도 파싱 대상이 아니다.

| 항목 | env | 기본값 |
|---|---|---|
| 자동 주문 킬 스위치 | `AI_AUTOTRADE` | `0` (꺼짐 — 판단 기록만) |
| 1회 주문금액 상한 | `AI_MAX_ORDER_KRW` | 1,000,000원 |
| 1회 주문수량 상한 | `AI_MAX_QTY` | 100주 |
| 종목당 최대 비중 | `AI_MAX_POSITION_PCT` | 평가액의 20% |
| 일일 최대 주문 건수 | `AI_MAX_ORDERS_PER_DAY` | 5건 |
| 대상 종목 수 | `AI_TOP_N` | 10 |
| 계좌 | `AI_ACCOUNT_ID` | 미설정 시 **주문 생략**(자동 선택 없음) |

- **킬 스위치**: `AI_AUTOTRADE != '1'`이면 주문만 멎고 판단 기록은 남는다.
  Actions에서는 저장소 Variable 하나(`AI_AUTOTRADE`)로 끈다 — 코드 수정·재배포 불필요.
  기본이 "꺼짐"인 이유는 fail-safe다. 시크릿 하나가 빠져도 주문이 나가지 않는다.
- **스키마 검증**(`validate`): 유니버스 밖 종목코드, 알 수 없는 action, 중복 종목,
  dict가 아닌 원소를 전부 버린다. 티커는 6자리 제로패딩, 근거는 200자 절단.
- **멱등성**: 위 2단계(판단 스킵) + `plan_orders`의 `(ticker, 오늘) in done` 이중 방어.
  둘 다 `--date`가 아니라 **오늘 KST**로 판정한다 — 실제 주문의 `ordered_at`이 오늘이라서다.
- **일일 건수 상한**은 `GET /orders?account_id=`로 조회한 **오늘** 기존 주문 수를 더해서 센다.
- **체결가 버퍼**: MARKET은 접수 시각이 아니라 다음 분봉에서 체결된다. 수량은
  체결가가 상한가(+30%)까지 튀어도 금액 상한·현금을 넘지 않게 `가격 × 1.3`으로 나눠 정한다.
- **현금 이중 사용 방지**: 한 배치 안에서 매수할 때마다 남은 현금을 차감한다.
- SELL은 보유 수량을 넘지 않고, 미보유 종목은 거부한다(엔진의 잔고 검증 이전 단계에서 컷).
- 파싱 실패·타임아웃(기본 300초)·`claude` 미설치는 전부 빈 리스트로 떨어뜨린다 —
  판단이 없으면 주문도 없다.

## 실행

```sh
uv run python decide.py --dry-run --top 5              # API 쓰기 없이 계획만
uv run --env-file ../.env python decide.py --top 10
uv run python test_decide.py                           # 파서·상한·멱등 단위 검증
```

`--dry-run` 출력 예 (2026-08-02 18:42 KST = 일요일, top 2, `AI_ACCOUNT_ID=1`):

```
INFO 유니버스 2종목: 005930,000660
INFO 프롬프트 552자 — claude -p 호출
INFO 판단 005930 HOLD — 1일 +26.8% 급등에 MA5 이격 +13.9%로 과열, 일봉 6개뿐이라 추격 진입 보류
INFO [dry-run] POST /ai-decisions {"ticker": "005930", "ts": "2026-08-02 18:42", "action": "HOLD", ...}
WARNING 주문 경로 스킵 — 장중 아님 2026-08-02 18:42 KST (평일 09:00~15:29만 주문)
```

`--date`를 과거로 주면 지표만 그날 기준이 되고 주문은 막힌다:

```
WARNING 주문 경로 스킵 — 지표 기준일 2026-07-31 != 오늘 2026-08-02 (--date는 지표 전용)
```

## 알려진 한계

- 14:10 실행 시점엔 collect(16:30 KST)가 아직 안 돌아 **당일 일봉이 없다** — 지표는 전
  거래일까지다. 수량은 `/quotes` 실시간가로 정하므로 주문 규모는 영향받지 않는다.
- 공휴일 판정은 `/quotes` 시세 유무로만 한다(달력 없음). 시세가 없으면 주문을 생략한다.
- `daily_prices`에 일봉이 적으면(현재 6거래일) MA20·거래량비가 `-`로 나가고 판단 근거가 얇다.
  일봉이 쌓이면 자동으로 채워진다.
- 등락률은 DB에 있는 인접 두 행으로 계산한다. 일봉에 결손일이 있으면 그 구간이 건너뛰어진다.
- 판단 성과는 `daily.py`의 `update_ai_returns`가 `ret_d5/d20/d60`에 채운다.
